# SprintMart — Trainer Answer Key

**Do not share this file with trainees.** This is where every deliberate change between phases gets documented as it's introduced: front-end changes that break a badly-written locator but not a well-written one, and genuine functional regressions a good assertion should catch.

## Phase 1 — baseline

Nothing to disclose yet. This is the first release: a correct, working catalog with no seeded issues. From Phase 2 onward, this file will have one entry per phase covering:

- **What changed in the markup**, and which locator strategies survive it vs. break on it.
- **What changed in behavior**, distinguishing a genuine regression (something a good assertion should catch) from an intentional feature change (something the user stories will call out directly).
- **Which user story or acceptance criterion** each change relates to, so you can map a student's failing test back to a specific requirement during review.

Keep this updated as each phase lands — it's the difference between "grading vibes" and being able to tell a student exactly where their suite should have caught something.
